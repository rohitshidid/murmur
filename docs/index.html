The gesture

One key. Two ways to use it.

Hold it and it's push-to-talk — recording stops the moment you let go. Or tap it and the mic locks open until you tap again, because holding a key down for a long thought is the single thing that stops people dictating anything longer than a sentence.

🎙️

It doesn't steal your cursor

The overlay is a non-activating panel — it cannot become the key window. Your text field keeps focus the whole time, which is the only reason there is somewhere to put the text when you stop talking.

↩︎

⌥⌘Z takes it back

Dictated the wrong thing into the wrong window? Undo removes it. Bounded to 30 seconds and to the app it went into, because past that nothing can prove the text on screen is still the text we put there.

🤝

It shares your Mac politely

Built to run alongside another dictation tool. The event tap inspects only its own keycode and passes every other keystroke through untouched — so give each app a different key and neither notices the other.

Cleanup

It writes down what you meant.

Raw speech-to-text is not usable text. A cleanup pass — Apple's on-device language model, or a deterministic rule pass if you'd rather — strips the fillers, restores punctuation and paragraphs, formats spoken lists, and honours mid-sentence corrections like "make that three, actually".

Two guards keep it in the hot path safely. It is bounded: past four seconds it falls back to the rule pass, because a stalled model must never cost you an utterance you already spoke. And it is guarded: output containing words you didn't say is rejected outright — which is what stops it answering your dictation instead of tidying it.

Screen context

It can see what you're looking at.

Say "hud panel dot swift" while that file is open and you get HUDPanel.swift — spelled the way it appears on your screen, not the way a general-purpose model guesses at it. Filenames, symbols, bundle IDs, branch names.

Three rules keep it from rewriting ordinary speech: a candidate must look like code (a camel hump, an underscore, a dot, a path separator), it can never be a single word, and a two-word form made entirely of common English is thrown away too.

It reuses the Accessibility grant the hotkey already needs — no second permission. The text is matched against one transcript and dropped: never stored, never added to history.

Per-app tone

The same sentence, dressed for where it lands.

A thought wants to be a paragraph in Mail, one lowercase line in Slack, and a bare comment in an editor. Nothing but the destination app can tell you which, so Murmur resolves the app at injection time and applies a tone rule for it.

The rules are yours to write, with one constraint the app enforces: they must be subtractive or structural, never additive. Say how to shape what you said; you cannot ask it to invent something you didn't.

Dictionary

A text file, not a database.

Names your engine will never get right go in a plain text file you can open in any editor. A bare line is a term to bias toward; X -> Y is a correction applied afterwards, deterministically. The file is watched, so editing it updates the app live and vice versa.

Biasing the engine is a nudge that promises nothing. Anything that has to be correct is fixed after the fact — which is why the corrections are a separate, testable pass, running the same vectors on macOS and on the in-progress Windows build.

~/Library/Application Support/Murmur/dictionary.txt
# a bare line is a term to bias toward
Anthropic
Vercel

# X -> Y is a correction, applied after

# off: whisper flow -> Wispr Flow

Meeting mode

Two tracks, so "you" is exact.

A second capture path records your microphone and your Mac's own audio as two separate tracks, transcribes both, diarizes the remote one, and produces an attributed transcript with timestamps — out to Markdown, plain text, SRT or WebVTT.

Keeping the tracks apart is the whole trick: you are attributed for free and exactly, and the diarizer only has to separate the remote voices from each other — never to pull your own voice out of a mixdown it dominates.

The system audio is taken with a CoreAudio process tap, not ScreenCaptureKit. The latter is less code and would ask for Screen Recording — a far broader grant than a dictation app has any business holding. The audio itself is never kept.

Permissions

Two grants, and why each one is unavoidable.

A dictation app asking for Accessibility looks alarming until you know what it is for. It is not optional and it cannot be requested silently, so here is the whole of it.

Accessibility Seeing the push-to-talk key, and inserting textOnly a session event tap can see fn and tell Right ⌘ from Left ⌘ — neither the Carbon hotkey API nor a global NSEvent monitor can Logging what you typeThe tap inspects its own keycode and passes everything else through untouched

🔒

Speech never leaves the Mac

Transcription and cleanup both run on-device. There is no account, no server, and nothing to opt out of — the app has no code path that uploads audio or text.

🗑️

Meeting audio isn't kept

A meeting is minutes of everyone in the room. The transcript is the thing the feature is for, so the recording is discarded once it exists.

📖

All of it is readable

About 7,000 lines of Swift, MIT-ish and open. The dictionary is a text file in Application Support; history clears with murmur://clear.

Getting started

Four steps, once.

Download and drag it in

Move Murmur into your Applications folder. Apple silicon, macOS 26 Tahoe or later. There is nothing else to install unless you choose Parakeet later.

Right-click → Open → Open

The app isn't signed by an identified developer, so a plain double-click is refused the first time.

Grant Accessibility, then relaunch

System Settings → Privacy & Security → Accessibility → add Murmur. Relaunching matters: the event tap can only be created once the grant exists.

Hold Right ⌘ and talk

The microphone prompt appears on that first dictation. Prefer a different key, or strict hold-to-talk with no tap-to-lock? Both are in Settings.

The honest catch with an unsigned build

macOS ties the Accessibility grant to a code-signing requirement, not to a path. These builds are ad-hoc signed, and an ad-hoc signature is different on every build — so after installing an update you will have to grant Accessibility again.

The symptom is nastier than it sounds: the toggle still shows as on while the app is reported untrusted, and flipping it changes nothing, because the stale row is the problem. Remove Murmur from the list and add it back — or reset the one row, always with the bundle ID, because a bare tccutil reset Accessibility wipes every app on the machine: 

tccutil reset Accessibility ai.pivotstudio.murmur
tccutil reset Microphone   ai.pivotstudio.murmur

Then quit System Settings entirely with ⌘Q before reopening it — that pane caches its list and will otherwise show the row you just deleted. Notarized, Developer ID-signed builds are on the list below, and they end this for good.

Or build it yourself — Xcode 26 and nothing else:

git clone https://github.com/rohitshidid/murmur.git
cd murmur
make install       # builds, bundles, signs, copies to /Applications, launches

# If you have a Developer ID certificate, the Makefile finds it and uses it —
# and then your Accessibility grant survives every rebuild.

Where it's up to

What isn't built yet.

The macOS app is in daily use. These are the things people ask for that are not there — listed because finding out after you install is worse than reading it here.

  • Command ModeSelect text, hold a second key, say "make this more formal." Needs an Accessibility read of the selection plus a model round-trip.
  • File transcriptionDrop in an audio or video file and get a transcript. The engine protocol needs no changes — only a reader that yields chunks from a file instead of the microphone.
  • MultilingualThe language is pinned at launch. Per-utterance choice and auto-detection aren't wired up.
  • OnboardingThere is no first-run window. The permissions are granted from the menu instead.
  • Signing & notarizationWhat ends the re-granting described above, and the reason the first launch needs a right-click today.
  • WindowsIn the repo as a dictionary engine plus a specification — no audio, hotkey, injection or UI yet. Both platforms already run the same correction vectors in CI. It is not a download.
